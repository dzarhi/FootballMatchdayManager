# לוח משחקים - מ.ס. אשדוד, ילדים ב'

אתר קטן ורספונסיבי (מחשב + טלפון) המציג לאוהדים ולהורים את משחקי הקבוצה: יום, תאריך,
שעה, שם המגרש וכפתור ניווט ישיר בוויז לכתובת המגרש.

זהו אתר **סטטי** (HTML/CSS/JS בלבד, ללא שרת/בסיס נתונים), כך שאפשר לארח אותו בחינם ב-GitHub Pages.

## מבנה הפרויקט

```
index.html          # העמוד הציבורי - לוח המשחקים
stats.html          # סטטיסטיקות ותוצאות מ.ס. אשדוד
standings.html      # טבלת הליגה
results.html        # תוצאות הליגה לפי מחזור
admin.html          # עמוד ניהול לעריכת המשחקים (לא לשיתוף פומבי!)
css/style.css        # עיצוב כללי, RTL ורספונסיבי
css/admin.css        # עיצוב טבלת הניהול
js/utils.js          # פונקציות עזר (תאריכים, קישור וויז, טעינת נתונים)
js/app.js            # לוגיקת התצוגה הציבורית
js/admin.js          # לוגיקת עמוד הניהול
js/league.js         # טעינה ותצוגה משותפות לעמודי הליגה
data/matches.json    # קובץ הנתונים - כאן נמצאים כל המשחקים
```

## הרצה מקומית

אין צורך בהתקנות. אפשר לפתוח שרת סטטי פשוט מהתיקייה, לדוגמה עם Python:

```powershell
python -m http.server 8000
```

ואז לפתוח בדפדפן: http://localhost:8000

(פתיחה ישירה של `index.html` בכפול-קליק לרוב לא תעבוד בגלל חסימת `fetch` לקבצים מקומיים - `file://`.)

## עדכון המשחקים

הנתונים לדוגמה בקובץ `data/matches.json` הם **placeholder** - יש להחליף אותם בנתונים האמיתיים
(יריבות, תאריכים, שעות וכתובות מדויקות של המגרשים).

יש שתי דרכים לעדכן:

1. **עריכה ידנית** - פתחו את `data/matches.json` בכל עורך טקסט ועדכנו את הערכים לפי הפורמט הקיים.
2. **דרך עמוד הניהול** (`admin.html`) - טופס/טבלה נוחים להוספה, עריכה ומחיקה של משחקים.
   שימו לב: מכיוון שהאתר סטטי (אין שרת), השינויים בעמוד הניהול נשמרים רק בדפדפן שלכם
   (localStorage). כדי שהעדכון יופיע לכל הצופים באתר החי:
   1. ערכו/הוסיפו משחקים בעמוד הניהול.
   2. לחצו "הורד קובץ מעודכן (JSON)".
   3. החליפו את הקובץ שהורד בקובץ `data/matches.json` בפרויקט.
   4. בצעו `git commit` + `git push` כדי לעדכן את האתר החי.

   עמוד הניהול אינו מוגן בסיסמה אמיתית (זה לא אפשרי באתר סטטי בלי שרת) - לכן אל תשתפו
   את הקישור אליו בפומבי, אלא רק בין מי שמעדכן את התוכן.

### פורמט רשומת משחק

```json
{
  "id": "מזהה ייחודי כלשהו",
  "opponent": "שם הקבוצה היריבה",
  "homeAway": "home או away",
  "matchType": "league / cup / training",
  "date": "YYYY-MM-DD",
  "time": "HH:MM",
  "homeGoals": "מספר גולי הקבוצה המארחת (אופציונלי, למשחקים שכבר היו)",
  "awayGoals": "מספר גולי הקבוצה האורחת (אופציונלי, למשחקים שכבר היו)",
   "extraTimeHomeGoals": "שערי הקבוצה המארחת בהארכה, אם משחק גביע הסתיים בתיקו בזמן החוקי",
   "extraTimeAwayGoals": "שערי הקבוצה האורחת בהארכה, אם משחק גביע הסתיים בתיקו בזמן החוקי",
   "penaltiesHomeGoals": "שערי הקבוצה המארחת בדו-קרב פנדלים, אם נשמר תיקו גם לאחר הארכה",
   "penaltiesAwayGoals": "שערי הקבוצה האורחת בדו-קרב פנדלים, אם נשמר תיקו גם לאחר הארכה",
  "venueName": "שם המגרש",
  "address": "כתובת מדויקת - משמשת לקישור הניווט בוויז",
  "notes": "הערה חופשית (אופציונלי)"
}
```

היום בשבוע מחושב אוטומטית מתוך התאריך, ואין צורך להזין אותו בנפרד.
שדות ה-`homeGoals`/`awayGoals` מוצגים כתוצאה (לדוגמה 3:1) רק במשחקים שכבר היו (לפי התאריך) ורק אם הוזנו.
שדות התוצאה בהארכה ובפנדלים זמינים בעמוד הניהול רק לאחר תיקו בגביע בשלב הקודם. באתר מוצגת התוצאה המצטברת לאחר הארכה, ובמקרה הצורך גם תוצאת דו-קרב הפנדלים.

## פרסום ב-GitHub Pages

1. צרו repository חדש ב-GitHub והעלו אליו את כל קבצי הפרויקט (`git init`, `git add .`,
   `git commit`, `git remote add origin ...`, `git push`).
2. בעמוד ה-repository ב-GitHub: **Settings → Pages**.
3. תחת "Build and deployment" בחרו **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`.
4. שמרו - לאחר דקה-שתיים האתר יהיה זמין בכתובת מהסוג
   `https://<username>.github.io/<repo-name>/`.
5. לכל עדכון נתונים: עדכנו את `data/matches.json`, בצעו commit + push, וה-Pages יתעדכן אוטומטית.

## תוצאות וטבלת ליגה מ־Vole

[עמוד הטבלה](standings.html) מציג את טבלת ילדים ב׳ מרכז, ו[עמוד התוצאות](results.html)
מציג תוצאות סופיות של כל קבוצות הליגה לפי מחזור, מתוך [Vole](https://vole.one.co.il/league/1248).
שורת מ.ס. אשדוד מודגשת. בשני העמודים מוצג מועד העדכון האחרון לפי שעון ישראל;
לאחר 24 שעות ללא עדכון מופיעה התראה. [עמוד הסטטיסטיקות](stats.html) נשאר ייעודי לנתוני מ.ס. אשדוד.

הנתונים נשמרים ב־[data/league.json](data/league.json), ולכן האתר אינו תלוי בגישה ישירה
מכל דפדפן ל־Vole. הסנכרון מוגדר לעונת 2026/27 בלבד, ליגה 1248, קבוצה 1243,
24 קבוצות ו־23 מחזורים. החלפת עונה או שינוי מבנה הליגה דורשים עדכון מבוקר של הסקריפט.
הסנכרון קורא את ממשק הנתונים שמשמש את העמוד; זה אינו API ציבורי מתועד, ושינוי באתר
המקור עשוי לחייב התאמה. האחריות להסדרת הרשאה לשימוש בנתונים מול המקור היא של מפעיל האתר.

### כללי שמירה על הנתונים

- נאספים כל המחזורים, ורק משחקים המסומנים כסופיים מוצגים כתוצאות.
- נבדקת התאמה בין הטבלה לתוצאות. נתונים חסרים או סותרים עוצרים את הסנכרון לפני כתיבה.
- תוצאות אשדוד מותאמות למשחקי ליגה מקומיים לפי מחזור, יריבה ובית/חוץ. התאמה לא חד־משמעית נרשמת כאזהרה ולא משנה את המשחק.
- תוצאות ידניות, גם חלקיות, נשמרות. תוצאה שיובאה אוטומטית יכולה להתעדכן רק אם לא נערכה מאז; המעקב נשמר בשדה `voleResult`.
- תאריכים, שעות, מגרשים, הערות, כתובות, סרטונים ומשחקי גביע ואימון אינם משתנים.
- משחקים אינם נמחקים. אם תוצאה סופית שנשמרה נעלמת מהמקור, נדרשת בדיקה ידנית.
- בהרצה ב־GitHub, שינוי מקביל בענף יכשיל את ה־push במקום לדרוס אותו. מריצים שוב לאחר בדיקת השינוי.

### בדיקה והרצה מקומית

נדרש Node.js 22 ומעלה עבור הסנכרון והבדיקות בלבד, לא לצפייה באתר:

```powershell
npm ci
npx playwright install chromium
npm test
npm run sync:check
npm run sync:vole
```

`sync:check` בודק את המקור ללא כתיבה. `sync:vole` שומר תמונת מצב חדשה ומעדכן תוצאות חסרות.
הבדיקות כוללות תצוגת מחשב וטלפון, כשל טעינה ושמירה על תוצאות ידניות.

### הפעלת העדכון האוטומטי

1. העלו את קבצי הפרויקט, כולל [התהליך](.github/workflows/site.yml) וקובץ הנעילה של npm, לענף `main`.
2. ב־GitHub: **Settings → Pages → Build and deployment → Source**, בחרו **GitHub Actions** במקום פרסום מענף.
3. ודאו ש־GitHub Actions פעיל ושמדיניות המאגר מאפשרת לתהליך לכתוב ל־`main` ולפרסם ל־Pages. אין צורך לשמור token אישי בקוד.
4. ב־**Actions → Sync league and deploy site → Run workflow**, הפעילו הרצה ראשונה ובדקו שהסתיימה בהצלחה.

התהליך רץ כל 6 שעות בדקה 17 לפי UTC, וגם ניתן להפעלה ידנית. GitHub אינו מבטיח שעת
הרצה מדויקת ועלול להשבית תזמון במאגר ציבורי ללא פעילות ממושכת. כשל מוצג ב־Actions והנתונים
הקודמים נשארים באתר. כל push של קבצי האתר מפעיל בדיקות ופרסום, אך אינו מבצע סנכרון נוסף.
הפרסום מופעל במפורש באותו תהליך: commit באמצעות `GITHUB_TOKEN` לבדו אינו מפעיל בניית Pages.
ההנחיות בסעיף זה מחליפות את בחירת **Deploy from a branch** שתוארה לעיל.

2. עדכנו את שורת ה-`<img src="assets/logo.png" ...>` בקבצי [index.html](index.html) ו-
   [admin.html](admin.html) כך שתצביע לקובץ החדש.
